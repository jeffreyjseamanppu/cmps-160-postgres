3. Lecture: SQL JOINs

3.1 Why JOINs Matter

Imagine a college database containing students and courses. Storing each student's name and each course's title repeatedly in one large table creates redundant data. Instead, a normalized design stores students, courses, and enrollments separately. JOINs reconnect that information when needed.

3.2 Understanding Table Relationships

The students table uses student_id as its primary key. The courses table uses course_id. The enrollments table uses foreign keys to connect a student to a course. This is a many-to-many relationship implemented through a junction table.

3.3 Create the Practice Database Tables

Open pgAdmin's Query Tool in a practice database and run the following SQL. The DROP TABLE commands reset only these three named practice tables; do not run them in a database containing work you need to preserve.

DROP TABLE IF EXISTS enrollments;
DROP TABLE IF EXISTS courses;
DROP TABLE IF EXISTS students;

CREATE TABLE students (
    student_id INT PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL
);

CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(100) NOT NULL
);

CREATE TABLE enrollments (
    enrollment_id INT PRIMARY KEY,
    student_id INT REFERENCES students(student_id),
    course_id INT REFERENCES courses(course_id),
    grade INT CHECK (grade BETWEEN 0 AND 100)
);

3.4 INNER JOIN

An INNER JOIN returns only rows with matching keys in both tables. Here, it shows students who have enrollment records.

SELECT s.first_name, s.last_name, e.course_id, e.grade
FROM students AS s
INNER JOIN enrollments AS e
    ON s.student_id = e.student_id
ORDER BY s.student_id, e.course_id;

Expected result: Four rows: Alex appears twice, Jordan once, and Taylor once. Casey does not appear because there is no matching enrollment.

3.5 LEFT JOIN

A LEFT JOIN retains every row from the table on the left, even when no match exists on the right. Missing right-side values appear as NULL.

SELECT s.first_name, s.last_name, e.course_id
FROM students AS s
LEFT JOIN enrollments AS e
    ON s.student_id = e.student_id
ORDER BY s.student_id, e.course_id;

Expected result: Five rows, including Casey with a NULL course_id.

3.6 RIGHT JOIN

A RIGHT JOIN retains every row from the table on the right. In this example, every course appears, even if no enrollment exists.

SELECT c.course_name, e.student_id
FROM enrollments AS e
RIGHT JOIN courses AS c
    ON e.course_id = c.course_id
ORDER BY c.course_id, e.student_id;

Expected result: Five rows, including Mobile Programming with a NULL student_id. A RIGHT JOIN can often be rewritten as a LEFT JOIN by reversing table order.

3.7 FULL OUTER JOIN

A FULL OUTER JOIN includes matched rows plus unmatched rows from either side. It is useful for comparing two sets and identifying missing relationships.

SELECT s.first_name, e.course_id
FROM students AS s
FULL OUTER JOIN enrollments AS e
    ON s.student_id = e.student_id
ORDER BY s.first_name NULLS LAST, e.course_id;

Expected result: Five rows. Casey is included without a course; this sample contains no enrollment with an unmatched student because the foreign key prevents it.

3.8 Joining Three Tables

Multiple JOIN clauses allow you to display student names, course titles, and grades in one result.

SELECT s.first_name, s.last_name,
       c.course_name, e.grade
FROM students AS s
INNER JOIN enrollments AS e
    ON s.student_id = e.student_id
INNER JOIN courses AS c
    ON e.course_id = c.course_id
ORDER BY s.last_name, c.course_name;

3.9 JOINs with Aggregates

JOINs can be combined with COUNT and GROUP BY to answer questions such as how many students are enrolled in each course. COUNT(e.enrollment_id) counts matching enrollment rows; unlike COUNT(*), it returns zero for a course without enrollments.

SELECT c.course_name,
       COUNT(e.enrollment_id) AS student_count
FROM courses AS c
LEFT JOIN enrollments AS e
    ON c.course_id = e.course_id
GROUP BY c.course_id, c.course_name
ORDER BY c.course_name;

Expected counts: Databases = 2, Web Development = 1, Cybersecurity = 1, Mobile Programming = 0.

3.10 Common Mistakes to Avoid

  • Omitting the ON condition and unintentionally creating many combinations of rows.
  • Joining unrelated columns rather than matching foreign and primary keys.
  • Using an INNER JOIN when unmatched records must be included.
  • Placing a filter on a right-side column in WHERE after a LEFT JOIN, which can eliminate NULL rows.
  • Using unqualified column names when both tables contain the same name.
