Final Project Overview

For your final project, you will independently design and build a complete relational database based on a topic that interests you.

This project is designed to bring together the major concepts covered throughout the semester. You will begin with an idea, design the database structure, create the tables, populate the database, manipulate the data, write queries, and create stored procedures.

You will also document your completed database using screenshots and demonstrate that your database works correctly.

Your Goal

Create a database that could realistically be used to manage information related to your chosen topic.

Your project should answer the following question:

"If someone actually needed a database for this topic, what information would they need to store and what questions would they need the database to answer?"

Choosing a Topic

Your database may be based on nearly any appropriate topic that interests you.

Examples include:

  • Sports Team or League
  • Video Game Collection
  • Music Library
  • Restaurant
  • Winery or Brewery
  • Auto Dealership
  • Gym or Fitness Center
  • Pet Adoption Center
  • Online Store
  • Movie Collection
  • Hotel
  • School
  • Hospital or Medical Office
  • Bookstore
  • Concert or Event Management
  • Another instructor-approved topic
Tip: Choose something you actually understand or enjoy. Knowing the topic will make it much easier to determine what data should be stored and how the tables should relate.

Project Phases

Phase 1 – Database Proposal

Before creating your database, submit a short proposal explaining what you plan to build.

Your proposal should contain:

  • Database name
  • Topic
  • Purpose of the database
  • Who would use the database
  • What information will be stored
  • At least five potential entities/tables

Phase 2 – ER Diagram

Design your database before writing SQL.

Your Entity Relationship Diagram must identify:

  • Tables / Entities
  • Attributes / Columns
  • Primary Keys
  • Foreign Keys
  • Relationships
  • Cardinality

Your ER diagram should clearly show how information moves between related tables.

Phase 3 – Create the Database

Write SQL scripts that create all required tables.

Your tables should include:

  • Appropriate data types
  • Primary keys
  • Foreign keys
  • NOT NULL constraints where appropriate
  • UNIQUE constraints where appropriate
  • CHECK constraints where appropriate

Phase 4 – Populate the Database

Create INSERT statements that add realistic data to your database.

Your completed database must contain at least 50 records distributed logically across your tables.

The data should make sense for your project. Avoid simply inserting random values that have no relationship to the scenario.

Phase 5 – Manipulate the Data

Demonstrate each major CRUD operation:

  • CREATE – INSERT new records.
  • READ – SELECT information.
  • UPDATE – Modify existing records.
  • DELETE – Remove records.

You must demonstrate at least:

  • 3 UPDATE operations
  • 3 DELETE operations

Phase 6 – Query the Database

Create at least 10 queries that answer useful questions about your data.

Your queries should demonstrate:

  • SELECT
  • WHERE
  • ORDER BY
  • Multiple conditions
  • JOIN
  • Aggregate functions
  • GROUP BY

At least three queries must retrieve information from multiple related tables.

Phase 7 – Stored Procedures

Create at least two stored procedures.

Your procedures should accomplish useful tasks related to your database.

Examples include:

  • Updating inventory
  • Changing a product price
  • Registering a student
  • Updating player statistics
  • Adding points to a customer account
  • Updating order status

Phase 8 – Documentation and Screenshots

Document your completed database using screenshots.

Your screenshots should show:

  1. Your completed ER Diagram
  2. Your database and tables
  3. Table data
  4. INSERT operation
  5. UPDATE operation
  6. DELETE operation
  7. SELECT queries
  8. JOIN query
  9. Aggregate query
  10. Stored procedure
  11. Stored procedure execution/results

Example CREATE TABLE Script

CREATE TABLE wine_types (
    wine_type_id SERIAL PRIMARY KEY,
    type_name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE wines (
    wine_id SERIAL PRIMARY KEY,
    wine_name VARCHAR(100) NOT NULL,
    wine_type_id INTEGER NOT NULL,
    vintage INTEGER,
    price DECIMAL(8,2) NOT NULL,
    quantity INTEGER DEFAULT 0,

    CONSTRAINT fk_wine_type
        FOREIGN KEY (wine_type_id)
        REFERENCES wine_types(wine_type_id)
);

CREATE TABLE customers (
    customer_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    phone VARCHAR(20)
);

CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    customer_id INTEGER NOT NULL,
    order_date DATE NOT NULL,
    total DECIMAL(10,2),

    CONSTRAINT fk_customer
        FOREIGN KEY (customer_id)
        REFERENCES customers(customer_id)
);

CREATE TABLE order_details (
    order_detail_id SERIAL PRIMARY KEY,
    order_id INTEGER NOT NULL,
    wine_id INTEGER NOT NULL,
    quantity INTEGER NOT NULL,
    unit_price DECIMAL(8,2) NOT NULL,

    FOREIGN KEY (order_id)
        REFERENCES orders(order_id),

    FOREIGN KEY (wine_id)
        REFERENCES wines(wine_id)
);

Example UPDATE

Assume five bottles of Pinot Meow were removed from inventory. 

UPDATE wines
SET quantity = quantity - 5
WHERE wine_name = 'Pinot Meow';

Example DELETE

DELETE FROM customers
WHERE customer_id = 10;
Think About It: What happens if customer 10 already has orders? The foreign key relationship may prevent the customer from being deleted. This protects the integrity of related data.

Example Business Queries

Find wines currently in stock:

SELECT wine_name, price, quantity
FROM wines
WHERE quantity > 0
ORDER BY wine_name;

Find wines under $25:

SELECT wine_name, price
FROM wines
WHERE price < 25
ORDER BY price;

Display customers and their orders:

SELECT
    c.first_name,
    c.last_name,
    o.order_id,
    o.order_date,
    o.total
FROM customers c
JOIN orders o
    ON c.customer_id = o.customer_id
ORDER BY o.order_date DESC;

Determine the best-selling wines:

SELECT
    w.wine_name,
    SUM(od.quantity) AS bottles_sold
FROM wines w
JOIN order_details od
    ON w.wine_id = od.wine_id
GROUP BY w.wine_name
ORDER BY bottles_sold DESC;

Example Stored Procedure

The winery could use a stored procedure to add bottles to inventory. 

CREATE OR REPLACE PROCEDURE update_wine_inventory(
    p_wine_id INTEGER,
    p_quantity INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE wines
    SET quantity = quantity + p_quantity
    WHERE wine_id = p_wine_id;

END;
$$;

Execute the procedure:

CALL update_wine_inventory(1, 12);

This adds 12 bottles to the inventory of wine ID 1.

Second Stored Procedure Example

CREATE OR REPLACE PROCEDURE update_wine_price(
    p_wine_id INTEGER,
    p_new_price DECIMAL
)
LANGUAGE plpgsql
AS $$
BEGIN

    UPDATE wines
    SET price = p_new_price
    WHERE wine_id = p_wine_id;

END;
$$;

Execute:

CALL update_wine_price(1, 22.00);
