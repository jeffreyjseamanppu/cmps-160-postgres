3. Lecture: Advanced Query Techniques

Part A — What is a subquery?

A subquery is a SELECT statement nested inside another SQL statement. The inner query produces a result used by the outer query. For example, to find wines priced above the average wine price:

SELECT wine_name, price
FROM wines
WHERE price > (SELECT AVG(price) FROM wines)
ORDER BY price DESC;

The inner SELECT returns a single average price. The outer SELECT filters wines against that value. This is a scalar subquery, because the inner query returns one value.

Part B — Multi-row subqueries using IN

IN tests whether a value is included in a set returned by a subquery. This example finds wines that appear in an order:

SELECT wine_name
FROM wines
WHERE wine_id IN (
  SELECT wine_id FROM order_items
);

Unlike a scalar subquery, the inner query can return multiple rows. EXISTS is often useful when checking for related records:

SELECT w.wine_name
FROM wines AS w
WHERE EXISTS (
  SELECT 1
  FROM order_items AS oi
  WHERE oi.wine_id = w.wine_id
);

Part C — Correlated subqueries

A correlated subquery refers to a column from its outer query. The following example identifies wines priced above the average within their own category:

SELECT w.wine_name, w.category, w.price
FROM wines AS w
WHERE w.price > (
  SELECT AVG(w2.price)
  FROM wines AS w2
  WHERE w2.category = w.category
);

The category comparison connects the inner query to the current outer row. Explain why this differs from comparing every wine against one overall average.

Part D — Views

A view is a named, reusable query. A regular PostgreSQL view does not store a separate snapshot of query results; its underlying query is used when the view is referenced.

CREATE VIEW premium_wines AS
SELECT wine_id, wine_name, category, price
FROM wines
WHERE price >= 22.00;

SELECT * FROM premium_wines
ORDER BY price DESC;

Views simplify reporting and reduce repeated SQL. They can also help expose selected columns, but they are not a complete security mechanism by themselves. Permissions and access design still matter.

CREATE OR REPLACE VIEW premium_wines AS
SELECT wine_id, wine_name, category, price
FROM wines
WHERE price >= 25.00;

DROP VIEW premium_wines;

For this example, CREATE OR REPLACE VIEW preserves the existing output column names, order, and types. A materialized view differs because it stores query results and requires refreshing to reflect changes.

Part E — Introduction to stored procedures

Stored procedures group database operations under a callable name. In PostgreSQL, procedures are defined with CREATE PROCEDURE and executed with CALL. This introductory example writes an audit message:

CREATE TABLE IF NOT EXISTS module7_audit (
  audit_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  message text NOT NULL,
  created_at timestamp DEFAULT CURRENT_TIMESTAMP
);

CREATE OR REPLACE PROCEDURE log_module7_demo()
LANGUAGE SQL
AS $$
  INSERT INTO module7_audit (message)
  VALUES ('Module 7 procedure executed');
$$;

CALL log_module7_demo();
SELECT * FROM module7_audit;

Discuss how procedures can help standardize repeatable database actions. Procedures are included as introductory material; the graded assignment emphasizes subqueries and views.

4. Hands-on Lab: Wine Inventory Reporting

Estimated time: 60–90 minutes | Software: pgAdmin 4

Step 1 — Create a practice database

In pgAdmin 4, create a database named module7_wine_lab. Connect to it, open Query Tool, and run the following SQL. Keep this separate from your semester project.

CREATE TABLE wines (
  wine_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  wine_name varchar(80) NOT NULL,
  category varchar(30) NOT NULL,
  price numeric(8,2) NOT NULL CHECK (price >= 0)
);

CREATE TABLE order_items (
  item_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  wine_id integer NOT NULL REFERENCES wines(wine_id),
  quantity integer NOT NULL CHECK (quantity > 0)
);

INSERT INTO wines (wine_name, category, price) VALUES
('Old Vine Zinfandel','Dry Red',25.00),
('Tempranillo','Dry Red',22.00),
('Syrah','Dry Red',24.00),
('Sauvignon Blanc','Dry White',20.00),
('Mango Mayhem','Fruit',20.00),
('Blackberry','Fruit',18.00);

INSERT INTO order_items (wine_id, quantity) VALUES
(1,3),(1,2),(2,4),(4,2),(5,6);

Step 2 — Run a scalar subquery

SELECT wine_name, price
FROM wines
WHERE price > (SELECT AVG(price) FROM wines);

Record the names and prices returned. Explain how the average is calculated.

Step 3 — Run an IN subquery

SELECT wine_name
FROM wines
WHERE wine_id IN (SELECT wine_id FROM order_items);

Identify which wines have appeared in orders.

Step 4 — Run a correlated subquery

SELECT w.wine_name, w.category, w.price
FROM wines w
WHERE w.price > (
  SELECT AVG(w2.price)
  FROM wines w2
  WHERE w2.category = w.category
);

Compare each wine against the average price in its category.

Step 5 — Create and query a sales view

CREATE VIEW wine_sales_summary AS
SELECT w.wine_id, w.wine_name,
       COALESCE(SUM(oi.quantity),0) AS bottles_sold,
       COALESCE(SUM(oi.quantity * w.price),0) AS revenue
FROM wines w
LEFT JOIN order_items oi ON oi.wine_id = w.wine_id
GROUP BY w.wine_id, w.wine_name;

SELECT * FROM wine_sales_summary
ORDER BY revenue DESC;

Explain why LEFT JOIN and COALESCE allow wines without orders to appear with zero sales.

Step 6 — Verify that the view reflects new data

INSERT INTO order_items (wine_id, quantity)
VALUES (3,5);

SELECT * FROM wine_sales_summary
ORDER BY revenue DESC;

Observe how the results change without recreating the view.
