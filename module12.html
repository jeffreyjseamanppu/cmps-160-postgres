Lecture: Intermediate Stored Procedures

1. Review: Procedures vs. Functions

A PostgreSQL procedure is created with CREATE PROCEDURE and invoked with CALL. A function is created with CREATE FUNCTION and can return a value or a result set through a SQL expression such as SELECT. Procedures are especially useful for coordinated data changes and, in eligible calling contexts, transaction control. Functions are often preferred for calculations and query-oriented results.

2. Build a Small Wine Store Database

We will use a wine-store example. The same concepts apply to a bookstore, inventory system, appointment system, or any approved final-project topic.

CREATE SCHEMA IF NOT EXISTS procedure_lab;
SET search_path TO procedure_lab, public;

CREATE TABLE IF NOT EXISTS products (
    product_id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    price NUMERIC(10,2) NOT NULL CHECK (price >= 0),
    stock_quantity INTEGER NOT NULL DEFAULT 0
        CHECK (stock_quantity >= 0)
);

CREATE TABLE IF NOT EXISTS inventory_log (
    log_id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    product_id INTEGER NOT NULL REFERENCES products(product_id),
    quantity_change INTEGER NOT NULL,
    reason VARCHAR(100) NOT NULL,
    changed_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO products (product_name, price, stock_quantity)
VALUES ('Merlot', 25.00, 20), ('Chardonnay', 22.00, 15);

SELECT * FROM products ORDER BY product_id;

3. Parameters and Validation: Add a Product

The procedure below uses input parameters and guards against missing names, negative prices, and negative inventory. Database constraints provide an additional layer of protection.

CREATE OR REPLACE PROCEDURE procedure_lab.add_product(
    IN p_name VARCHAR,
    IN p_price NUMERIC,
    IN p_quantity INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_name IS NULL OR BTRIM(p_name) = '' THEN
        RAISE EXCEPTION 'Product name is required';
    END IF;
    IF p_price IS NULL OR p_price < 0 THEN
        RAISE EXCEPTION 'Price must be zero or greater';
    END IF;
    IF p_quantity IS NULL OR p_quantity < 0 THEN
        RAISE EXCEPTION 'Quantity must be zero or greater';
    END IF;

    INSERT INTO procedure_lab.products
        (product_name, price, stock_quantity)
    VALUES (BTRIM(p_name), p_price, p_quantity);
END;
$$;

CALL procedure_lab.add_product('Pinot Noir', 28.00, 12);
SELECT * FROM procedure_lab.products ORDER BY product_id;

4. Conditional Logic and Safe Updates

Use IF NOT FOUND after an UPDATE to detect an ID that does not exist. Notice that FOUND describes whether the preceding SQL statement affected a row.

CREATE OR REPLACE PROCEDURE procedure_lab.update_product_price(
    IN p_product_id INTEGER,
    IN p_new_price NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_new_price IS NULL OR p_new_price < 0 THEN
        RAISE EXCEPTION 'New price must be zero or greater';
    END IF;

    UPDATE procedure_lab.products
       SET price = p_new_price
     WHERE product_id = p_product_id;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Product ID % was not found', p_product_id;
    END IF;
END;
$$;

5. Coordinated Changes: Inventory and Audit Logging

This procedure modifies inventory and inserts an audit record in the same transaction. If an exception occurs, both changes roll back together (assuming the exception is not caught and suppressed).

CREATE OR REPLACE PROCEDURE procedure_lab.adjust_inventory(
    IN p_product_id INTEGER,
    IN p_change INTEGER,
    IN p_reason VARCHAR
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_current_stock INTEGER;
BEGIN
    IF p_change IS NULL OR p_change = 0 THEN
        RAISE EXCEPTION 'Change must be nonzero';
    END IF;
    IF p_reason IS NULL OR BTRIM(p_reason) = '' THEN
        RAISE EXCEPTION 'Reason is required';
    END IF;

    SELECT stock_quantity INTO v_current_stock
      FROM procedure_lab.products
     WHERE product_id = p_product_id
     FOR UPDATE;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Product ID % does not exist', p_product_id;
    END IF;
    IF v_current_stock + p_change < 0 THEN
        RAISE EXCEPTION 'Insufficient stock: available %, change %',
            v_current_stock, p_change;
    END IF;

    UPDATE procedure_lab.products
       SET stock_quantity = stock_quantity + p_change
     WHERE product_id = p_product_id;

    INSERT INTO procedure_lab.inventory_log
        (product_id, quantity_change, reason)
    VALUES (p_product_id, p_change, BTRIM(p_reason));
END;
$$;

-- Substitute an existing product ID:
-- CALL procedure_lab.adjust_inventory(1, -2, 'Customer purchase');
-- SELECT * FROM procedure_lab.inventory_log ORDER BY log_id;

6. Safe Deletes and Foreign Keys

Deleting a product that has inventory-log references would violate the foreign key. This example deliberately refuses deletion of referenced products rather than erasing historical records.

CREATE OR REPLACE PROCEDURE procedure_lab.delete_product(
    IN p_product_id INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF EXISTS (
        SELECT 1 FROM procedure_lab.inventory_log
         WHERE product_id = p_product_id
    ) THEN
        RAISE EXCEPTION 'Cannot delete product %: inventory history exists',
            p_product_id;
    END IF;

    DELETE FROM procedure_lab.products
     WHERE product_id = p_product_id;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Product ID % was not found', p_product_id;
    END IF;
END;
$$;

-- Test on a product with no log entries, using its actual ID:
-- CALL procedure_lab.delete_product(3);

7. Intermediate Concepts: INOUT, Exceptions, and Transactions

INOUT parameters can provide values back to the caller. RAISE NOTICE produces informational messages, while RAISE EXCEPTION aborts the current operation unless handled. PostgreSQL procedures may issue COMMIT or ROLLBACK only in supported top-level CALL contexts; they cannot do so inside a CALL executed within an explicit transaction block. For this module, let PostgreSQL manage each successful CALL as a transaction, and use an explicit transaction for safe experiments.

BEGIN;
-- Use an existing product ID and valid values:
-- CALL procedure_lab.update_product_price(1, 99.00);
SELECT * FROM procedure_lab.products ORDER BY product_id;
ROLLBACK;  -- Undo changes made in this demonstration transaction.
Important: Run each practice statement separately when directed. If a statement raises an exception inside an explicit transaction, issue ROLLBACK before continuing. Never use an unqualified DELETE or UPDATE on your final-project database.

  1. Open pgAdmin 4, connect to your PostgreSQL server, select your practice database, and open Tools → Query Tool.
  2. Run the schema and table setup script above. Expand Schemas → procedure_lab → Tables and verify that the tables exist.
  3. Create the four procedures. In pgAdmin, refresh Schemas → procedure_lab → Procedures to see them.
  4. Run SELECT * FROM procedure_lab.products ORDER BY product_id; and record actual IDs.
  5. Use CALL procedure_lab.add_product('Riesling', 21.00, 8); and verify the inserted row.
  6. Update that new product’s price using update_product_price, then SELECT to confirm the result.
  7. Adjust its inventory by -3 using adjust_inventory, then query both products and inventory_log.
  8. Try an invalid stock adjustment, such as -999. Capture the error and confirm inventory was not changed.
  9. Add a separate disposable product and delete it using delete_product. Confirm that it is gone. Attempt to delete a product with an inventory-log entry and explain the foreign-key safeguard.
  10. Demonstrate a reversible change using BEGIN, a valid CALL, SELECT, and ROLLBACK.
