Why Database Design Matters

Before we create tables in PostgreSQL, we need to understand what information should be stored and how that information relates to other data.

Key Idea:

A relational database separates information into logical tables and connects those tables through relationships.

Entities and Attributes

What is an Entity?

An entity is a person, place, object, event, or concept that we need to store information about.

Examples in a sports database:

TEAM PLAYER COACH GAME STADIUM

What is an Attribute?

An attribute is a characteristic or property of an entity.

TEAM ------------------ team_id team_name city state
PLAYER ------------------ player_id first_name last_name position jersey_number
Think About It:

If you were building a database for a winery, what entities would you need?

Possible entities:

CUSTOMER WINE ORDER CATEGORY

A WINE entity might contain:

WINE ------------------ wine_id wine_name wine_type vintage price

Primary Keys and Foreign Keys

Primary Key

A primary key uniquely identifies each record in a table.

Bad Primary Key: 
player_name

Two players may have the same name.

Better Design: 
player_id
PLAYER ------------------ player_id PK first_name last_name position

Primary keys should:

  • Be unique.
  • Never be NULL.
  • Identify exactly one row.

Foreign Key

A foreign key connects one table to another table.

TEAM ------------------ team_id PK team_name city PLAYER ------------------ player_id PK first_name last_name position team_id FK

The foreign key team_id tells us which team each player belongs to.

team_id team_name city

Table Relationships

One-to-One

EMPLOYEE 1 -------- 1 EMPLOYEE_BADGE

One employee has one employee badge.

One-to-Many

TEAM 1 -------- * PLAYER

One team can have many players.

One player belongs to one team.

Rule:

In a one-to-many relationship, the foreign key normally goes on the many side.

Many-to-Many

STUDENT * -------- * COURSE

A student can take many courses.

A course can contain many students.

A direct many-to-many relationship must normally be resolved using another table.

STUDENT | | 1 | * ENROLLMENT * | | 1 | COURSE
ENROLLMENT ------------------ student_id FK course_id FK semester grade

The ENROLLMENT table is often called a:

  • Junction table
  • Bridge table
  • Associative entity

Entity Relationship Diagrams

An Entity Relationship Diagram, or ERD, is a visual blueprint of a database.

TEAM ------------------ PK team_id team_name city 1 | | * PLAYER ------------------ PK player_id first_name last_name position FK team_id

ERDs help us design the database before creating tables in PostgreSQL.

Key Question:

What are the entities, and how are they related?

Instructor-Led Design Exercise

Winery Database

A winery sells multiple wines. Each wine belongs to a wine category. Customers can place orders. Each order can contain multiple wines, and each wine may appear on many different orders.

Class Question:

What entities do we need?

Possible entities:

CUSTOMER WINE CATEGORY ORDER ORDER_ITEM

Relationships

CATEGORY 1 | * WINE CUSTOMER 1 | * ORDER ORDER 1 | * ORDER_ITEM * | 1 WINE

ORDER_ITEM Table

ORDER_ITEM ------------------ order_item_id PK order_id FK wine_id FK quantity price
Question:

Why can't we simply place wine_id inside the ORDER table?

Because one order can contain multiple wines.

Question:

Why can't we place order_id inside the WINE table?

Because the same wine may appear on thousands of different orders.

Point Park University Course Registration System

Point Park University needs a database to track students, professors, courses, and course enrollment.

Each student has an ID, first name, last name, email, and major. Professors have an ID, name, email, and department. A professor can teach multiple courses. Students can enroll in multiple courses, and each course can contain multiple students. The university also needs to record the semester and final grade for each enrollment.

Step 1 - Identify the Entities

Determine the major objects that must be stored in the database.

Step 2 - Identify Attributes

Define the information that should be stored for each entity.

Step 3 - Identify Primary Keys

Choose a unique identifier for every entity.

Step 4 - Identify Relationships

Determine whether the relationships are one-to-one, one-to-many, or many-to-many.

Step 5 - Create an ERD

Draw an Entity Relationship Diagram showing the tables, primary keys, foreign keys, and relationships.

Possible Solution

STUDENT ------------------ student_id PK first_name last_name email major PROFESSOR ------------------ professor_id PK first_name last_name email department COURSE ------------------ course_id PK course_code course_name credit_hours professor_id FK ENROLLMENT ------------------ enrollment_id PK student_id FK course_id FK semester grade

Relationships

PROFESSOR 1 -------- * COURSE STUDENT 1 -------- * ENROLLMENT COURSE 1 -------- * ENROLLMENT

PostgreSQL Example

CREATE TABLE professor (
    professor_id INTEGER PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    email VARCHAR(100),
    department VARCHAR(100)
);

CREATE TABLE student (
    student_id INTEGER PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    email VARCHAR(100),
    major VARCHAR(100)
);

CREATE TABLE course (
    course_id INTEGER PRIMARY KEY,
    course_code VARCHAR(20),
    course_name VARCHAR(100),
    credit_hours INTEGER,
    professor_id INTEGER,
    FOREIGN KEY (professor_id)
        REFERENCES professor(professor_id)
);

CREATE TABLE enrollment (
    enrollment_id INTEGER PRIMARY KEY,
    student_id INTEGER,
    course_id INTEGER,
    semester VARCHAR(30),
    grade VARCHAR(5),
    FOREIGN KEY (student_id)
        REFERENCES student(student_id),
    FOREIGN KEY (course_id)
        REFERENCES course(course_id)
);

Module 2 Summary

Before building a database, always ask:

  1. What information do I need to store?
  2. What are my entities?
  3. What attributes belong to each entity?
  4. What uniquely identifies each record?
  5. How are the entities related?
  6. Where should foreign keys be placed?
  7. Do I need a junction table?
Main Takeaway:

Do not start by creating tables. Start by understanding the data and how the information relates to everything else.

Relational Database Design & Data Modeling

In this assignment, you will design a relational database based on a real-world scenario. Your goal is to identify the entities, attributes, primary keys, foreign keys, and relationships before creating the database.

Assignment Objective:

Demonstrate your understanding of relational database design by transforming business requirements into a logical database model.

Scenario: Sports League Database

You have been asked to design a database for a sports league. The league contains multiple teams. Each team has players and a coach. Teams play games against other teams at different venues.

The database should be able to store information about:

  • Teams
  • Players
  • Coaches
  • Games
  • Venues

Each team should have a team name, city, and state. Each player should have a first name, last name, jersey number, and position.

Each coach should have a first name and last name. Each game should record the teams participating, the date of the game, and the venue where the game is played.

Part 1 - Identify the Entities

Identify all entities that should exist in your database.

For each entity, briefly explain what the entity represents.

Part 2 - Define the Attributes

List the attributes that should be stored for each entity.

Example:

TEAM ------------------ team_id team_name city state

Part 3 - Identify Primary Keys

Identify a primary key for every table.

Clearly mark each primary key using: 

PK

Example:

TEAM ------------------ team_id PK team_name city state

Part 4 - Identify Foreign Keys

Determine where foreign keys are required to connect your tables.

Clearly mark foreign keys using: 

FK

Part 5 - Identify the Relationships

Identify the relationships between your entities.

For each relationship, indicate whether it is:

  • One-to-One
  • One-to-Many
  • Many-to-Many

Example:

TEAM 1 -------- * PLAYER

Part 6 - Create an Entity Relationship Diagram

Create an Entity Relationship Diagram (ERD) showing your complete database design.

Your ERD must clearly show:

  • All tables/entities
  • Attributes
  • Primary keys
  • Foreign keys
  • Relationships between tables
  • Relationship cardinality

You may create your ERD using a tool such as:

  • Microsoft Visio
  • Another approved ERD tool

Part 7 - Design Explanation

Write a short explanation of your database design. Your explanation should be approximately 1/2 to 1 page.

Discuss:

  • Why you selected your entities.
  • How the tables are related.
  • Why you selected your primary keys.
  • Where foreign keys are required.
  • Any many-to-many relationships you identified.
