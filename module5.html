Module 5 Overview

In the previous modules, we focused on designing relational databases, creating tables, defining primary and foreign keys, and inserting data into PostgreSQL.

This module shifts our focus from building databases to retrieving information from them.

You will learn how to use the SQL SELECT statement to retrieve information, filter records, sort results, search for patterns, and combine information stored across multiple tables.

These skills form the foundation for database reporting, analytics, web applications, business intelligence systems, and virtually every application that interacts with a relational database.

Lecture: Querying Data with SQL

1. The SELECT Statement

The SELECT statement retrieves information stored inside a database table.

The most basic query is:

SELECT *
FROM customers;

The asterisk (*) means return all columns from the table.

In many situations, however, we only need certain columns. 

SELECT first_name, last_name, email
FROM customers;

2. Column Aliases

The AS keyword allows us to provide a temporary name for a column in the query results. 

SELECT
    first_name AS "First Name",
    last_name AS "Last Name"
FROM customers;

3. Filtering Data with WHERE

The WHERE clause allows us to return only records that meet a specific condition. 

SELECT *
FROM products
WHERE price > 25;

Common comparison operators include:

Operator Description
= Equal
<> Not equal
> Greater than
< Less than
>= Greater than or equal
<= Less than or equal

4. AND, OR, and NOT

Multiple conditions can be combined using logical operators. 

SELECT *
FROM products
WHERE price > 20
AND category = 'Electronics';
SELECT *
FROM customers
WHERE state = 'PA'
OR state = 'OH';

5. BETWEEN

BETWEEN searches for values within a range. 

SELECT *
FROM products
WHERE price BETWEEN 25 AND 100;

6. IN

IN allows us to compare a value against multiple possible values. 

SELECT *
FROM customers
WHERE state IN ('PA', 'OH', 'WV');

7. Searching with LIKE

The LIKE operator allows us to search for patterns inside text. 

SELECT *
FROM customers
WHERE last_name LIKE 'S%';

The percent sign (%) represents zero or more characters. 

SELECT *
FROM customers
WHERE email LIKE '%gmail.com';

8. Working with NULL

NULL represents a missing or unknown value.

We do not test NULL values using the normal equality operator. 

SELECT *
FROM customers
WHERE phone IS NULL;
SELECT *
FROM customers
WHERE phone IS NOT NULL;

9. Sorting Results

The ORDER BY clause controls how query results are sorted. 

SELECT *
FROM products
ORDER BY price ASC;

Descending order:

SELECT *
FROM products
ORDER BY price DESC;

10. DISTINCT

DISTINCT removes duplicate values from query results. 

SELECT DISTINCT state
FROM customers;

11. LIMIT

PostgreSQL's LIMIT clause controls the number of rows returned. 

SELECT *
FROM products
ORDER BY price DESC
LIMIT 5;

This query returns the five most expensive products.

12. Why Do We Need JOINs?

Relational databases intentionally divide information into multiple tables. This prevents unnecessary duplication and improves data integrity.

Consider the following tables:

customers

customer_id
first_name
last_name
email

orders

order_id
customer_id
order_date
total

The customer_id column creates the relationship between these tables.

13. INNER JOIN

An INNER JOIN returns records where matching values exist in both tables. 

SELECT
    customers.first_name,
    customers.last_name,
    orders.order_id,
    orders.order_date
FROM customers
INNER JOIN orders
    ON customers.customer_id = orders.customer_id;

14. Table Aliases

Table aliases make JOIN queries shorter and easier to read. 

SELECT
    c.first_name,
    c.last_name,
    o.order_id,
    o.order_date
FROM customers c
INNER JOIN orders o
    ON c.customer_id = o.customer_id;

15. Joining Multiple Tables

Queries can combine information from more than two tables. 

SELECT
    c.first_name,
    c.last_name,
    o.order_id,
    p.product_name,
    oi.quantity
FROM customers c
INNER JOIN orders o
    ON c.customer_id = o.customer_id
INNER JOIN order_items oi
    ON o.order_id = oi.order_id
INNER JOIN products p
    ON oi.product_id = p.product_id;

This query demonstrates the real power of relational databases. Information stored across four separate tables can be combined into one meaningful result.

  6. Write a query using OR.
