Module 8: Advanced SQL – Views, CTEs, and Window Functions

Welcome to Module 8! Last week, we explored SQL subqueries and how nested queries can retrieve and filter information from a database. This week, we will expand those skills by learning three powerful PostgreSQL features: Views, Common Table Expressions (CTEs), and Window Functions.

These techniques are commonly used in database development, reporting, analytics, and business applications to organize complex SQL statements and extract meaningful information.

Module Learning Objectives

  • Explain the purpose of SQL Views and their benefits.
  • Create and query reusable Views in PostgreSQL.
  • Develop Common Table Expressions using the WITH clause.
  • Compare CTEs with traditional SQL subqueries.
  • Use ROW_NUMBER(), RANK(), and DENSE_RANK().
  • Apply window functions to business reporting and analysis.

1. Lecture: Advanced SQL Techniques

Part 1: SQL Views

A View is a named SQL query that can be accessed similarly to a table. Standard PostgreSQL Views do not independently store the query results. Instead, PostgreSQL executes the underlying query when the View is accessed.

Example: Creating a Customer Orders View

CREATE VIEW customer_orders AS
SELECT
    c.customer_id,
    c.customer_name,
    o.order_id,
    o.total_amount
FROM customers c
JOIN orders o
    ON c.customer_id = o.customer_id;

Query the View:

SELECT *
FROM customer_orders
WHERE total_amount > 100;

Part 2: Common Table Expressions

A Common Table Expression, or CTE, is a temporary named result set defined within a SQL statement using the WITH keyword. CTEs are useful for breaking complex queries into smaller, readable sections.

Example: Total Spending by Customer

WITH customer_totals AS (
    SELECT
        customer_id,
        SUM(total_amount) AS total_spent
    FROM orders
    GROUP BY customer_id
)
SELECT *
FROM customer_totals
WHERE total_spent > 500;

Part 3: Window Functions

Window Functions perform calculations across related rows while preserving the individual rows in the query results. Unlike GROUP BY, they do not automatically collapse records into one row per group.

Example: Ranking Orders by Amount

SELECT
    order_id,
    customer_id,
    total_amount,
    RANK() OVER (
        ORDER BY total_amount DESC
    ) AS order_rank
FROM orders;

Example: Running Total

SELECT
    order_id,
    total_amount,
    SUM(total_amount) OVER (
        ORDER BY order_id
        ROWS BETWEEN UNBOUNDED PRECEDING
        AND CURRENT ROW
    ) AS running_total
FROM orders;
